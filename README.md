# RetailPilot 零售智航

零售经营数据分析工作空间。可导入实际业务系统导出的门店、商品、订单和订单明细 CSV / Excel，校验后发布不可变快照，用于看板、受限分析、报告审核与导出。

本项目采用 [MIT 开源许可证](LICENSE)。

## 首次使用

需要 Node.js 22+、Python 3.11+ 和 uv。在项目根目录执行一条命令即可启动前端和后端：

```sh
npm run dev
```

启动脚本会检查端口、补装缺失的项目依赖，并在数据库没有账号时引导创建管理员 `owner`（密码至少 12 位，需输入两次；终端不显示密码，也不写入命令历史）。已有账号时直接启动，不修改账号或密码。首次安装依赖需要联网；系统工具需提前安装。

看到“RetailPilot 已启动”后，打开 <http://127.0.0.1:5173>，使用管理员账号登录。前端修改会自动刷新，后端修改会自动重启。在同一个终端按 `Ctrl+C` 会同时关闭两个服务；任一服务意外退出也会关闭另一个。端口 5173 或 8000 被占用时脚本会报错，不会终止其他程序或自动换端口。

如果只需要运行构建后的版本，也可以执行：

```sh
npm start
```

该命令同样准备依赖和首次账号，再构建前端，由后端统一提供网页与 API；打开 <http://127.0.0.1:8000>。此模式没有热更新。两种模式都只监听本机，不要同时运行。

新安装默认使用 `.data/retailpilot-live.db`，从空账号与空数据开始，不会自动写入交易记录。原先的 `.data/retailpilot.db` 不会被修改或自动迁入。可通过 `RETAILPILOT_DB` 指向另一份数据库；如指向旧演示库，旧数据仍会显示。

管理员可在「权限与配置 → 模型配置」填写服务地址、模型名称和 API Key，测试连接后保存，无需编辑 `.env` 或重启服务。新工作空间默认使用规则模式。部署者仍可通过环境变量提供初始配置，示例见 `.env.example`；启动脚本不自动加载 `.env`。升级依赖时执行 `npm ci` 和 `uv sync --frozen`；自动准备只补装缺失依赖，不替代升级同步。

## 前端与后端结构

项目已经实现前后端分离，不是只有静态前端：

| 部分 | 位置与技术                        | 职责                                                                 |
| ---- | --------------------------------- | -------------------------------------------------------------------- |
| 前端 | `src/`，React + TypeScript + Vite | 登录页、经营看板、数据中心、分析、报告、权限配置和审计页面           |
| 后端 | `backend/`，Python + FastAPI      | 登录会话、权限校验、数据导入校验、指标计算、任务调度、报告审核与导出 |
| 存储 | `.data/`，SQLite                  | 持久化账号、经营数据版本、任务、报告和审计记录，无需另装数据库服务   |

开发模式下，浏览器访问 5173，前端通过 `/api` 请求后端，Vite 将请求代理到 8000。后端接口文档位于 <http://127.0.0.1:8000/docs>。构建模式下由 FastAPI 提供 `dist/` 中的前端文件，所以只需要一个服务进程。默认分析采用规则工作流，不需要模型 API 密钥。

需要单独调试时，仍可分别使用 `npm run dev:frontend`（仅前端）和 `npm run server`（仅后端）；通常使用上面的统一启动命令即可。

## 注册新账号

管理员完成首次初始化后，其他用户可在登录页点击“注册新账号”，填写账号、姓名、密码和确认密码。账号为 3–40 位字母、数字、下划线、点或连字符，密码至少 12 位。注册成功后返回登录页，使用新账号登录。

自行注册的账号默认是“门店人员”，没有任何门店数据授权，也没有管理员权限。管理员用 `owner` 或其他管理账号登录，在“权限与配置 → 账号与门店授权”找到新账号、编辑权限，分配业务角色和门店。新用户重新登录后即可按授权使用。管理员仍可直接新建账号。

相同账号不能重复注册；每个来源 IP 在 10 分钟内最多尝试注册 10 次。首次管理员仍通过启动脚本创建，公开注册不能替代管理员初始化。

## 接入实际业务数据

1. 管理员在“数据中心”下载四张 CSV 模板，或按模板字段准备业务系统导出文件。每批需包含 `stores`、`products`、`orders`、`items` 四表；单批总量不超过 20 MB，编码为 UTF-8。
2. 上传文件并填写具体数据来源，例如系统名称、导出日期或文件出处。字段名不同可在页面映射。服务会检查主外键、金额、退款、数量及明细对账，阻断错误需在源文件修正。
3. 校验通过后核对覆盖日期、快照时间及质量警告，再发布数据版本。版本保存上传数据的副本、来源和校验指纹；历史报告继续引用原快照。
4. 用户可在登录页自行注册，或由管理员在“权限与配置”创建业务账号；管理员按实际门店 ID 授权，并按需要调整业务角色。管理员默认没有经营数据查看权限，如需查看，应给自己的账号配置相应门店范围和分析或管理角色。
5. 有授权的账号可查看看板、按完整自然月提问、生成报告并走审核流程。

系统不会判断上传文件是否来自真实交易系统；数据真实性须由提供方确认。`examples/benchmark/` 仅用于开发测试，不能作为真实经营数据。

## 当前功能与边界

- 自助注册、登录、退出、自助修改密码、管理员禁用/重置、注册与登录限流、HttpOnly 会话、角色和门店授权、操作审计。
- CSV / Excel 四表导入、字段映射、质量校验、问题清单与不可变快照。行序不影响业务指纹；相同内容、覆盖声明和快照时间禁止重复发布，变化的声明可发布新版本。
- 净销售额、有效订单数、客单价、净销量，按日期、门店和版本筛选；规则问数按所问指标分别计算比较值、变化和门店排名，支持多指标问题。
- 持久化排队、真实阶段记录、取消/超时/重启恢复、证据核验、报告审核修订、Markdown 和浏览器打印 / 保存 PDF；逐条建议记录负责人、到期日、行动和复核指标。
- 页面、日期、任务和报告地址可恢复；历史摘要分页，报告搜索与权限筛选在服务端完成。
- 默认使用确定性规则工作流；管理员可在网页配置可选模型、测试连接、更新或清除密钥、切回规则模式。模型只检查批准的计划、选择证据关联的复核建议，尚未做真实模型效果验收。问题需包含完整自然月和支持的指标；同比比较去年同月，环比比较上月，覆盖不足会请求澄清。当前一次可选一个门店或一个地区，多地区合并/对比需调整问题；计算结果不等于经营原因确认。
- 读取经营数据须同时具备业务角色（分析、管理或门店）和门店授权。管理员可导入、发布与配置账号；只有管理员角色时不开放经营看板、任务或报告读取。历史报告和修订沿用生成时的指标版本，正式导出需原始数据版本可用且证据一致。
- 默认本地部署，已提供健康检查、备份恢复、数据库迁移及可选 HTTPS 服务配置，尚未部署到真实远程环境。没有成本、库存、客流或活动数据，不能生成毛利、库存、预测和因果结论。
- Excel 使用 stores、products、orders、items 四张工作表，仅导入值；拒绝公式、宏及外部链接。成交时间填写带 +08:00 的 ISO 文本，Excel 文件和四表转换结果均不超过 20 MB。
