# 本地运维与可选远程部署

更新：2026-10-12。已补充网页模型配置；没有对外发布网站，也没有修改正式数据库。

## 数据库升级与回退

SQLite 只放在本机磁盘，不放在网络共享目录。升级前先备份，停止旧服务，保留旧程序目录，再安装新程序。首次启动会把内嵌版本数据迁到独立数据表和版本化查询表，`PRAGMA user_version` 升到 2；交易数值和报告证据保留。新程序拒绝打开比自身更新的数据库。

```sh
uv run python -m backend.manage backup /你的备份目录/retailpilot-before-upgrade.db
```

备份使用 SQLite 在线备份接口，校验完整性，文件权限为 600；已存在的备份文件不会被覆盖。应把备份放到另一块磁盘或自己的备份服务，并定期试恢复。数据库包含业务数据和账号哈希，备份按同样的权限管理。

恢复前必须停止全部服务进程。恢复会保留当前库的另一份备份，校验输入、迁移并清除登录会话：

```sh
uv run python -m backend.manage restore /你的备份目录/retailpilot-before-upgrade.db --service-stopped
```

`--service-stopped` 是操作者确认，不是进程探测。不要在服务仍运行时传入。若需回到旧程序，恢复与旧程序匹配的旧备份，不能只替换程序文件。

## 账号与服务状态

管理员可禁用账号和重置密码。禁用与重置使该账号已有会话失效；授权变更由每次请求和每个任务阶段重新检查。不能禁用自己或移除自己的管理员角色。登录使用持久化的账号/IP 两个限额，账号 10 分钟内最多 5 次失败，IP 最多 30 次失败；未知账号也计入。

`GET /api/health` 检查数据库连接并返回最小状态。任务错误日志只记录任务 ID、阶段和错误类型。业务操作审计通过“操作日志”查看；日志不记录密码和模型密钥。队列每个进程可调度，但全数据库同时最多两项；租约每 5 秒续约，30 秒到期，整体任务 120 秒超时。排队任务保留；中断任务失败后由用户重试。

## 可选模型配置

新工作空间默认使用规则模式。管理员登录后进入「权限与配置 → 模型配置」，选择「大模型协作」，填写服务地址（含 `/v1` 或供应商的对应接口前缀）、模型名称和 API Key。可选服务必须支持 Chat Completions 的 `json_schema` 严格输出。

1. 点击「测试连接」，以当前草稿发起一次小型结构化输出请求，不包含经营数据，不保存配置；该请求可能产生供应商费用，并计入每日调用预算。测试通过仅表示该次连接和基础结构化输出可用，不等于完成真实分析效果验收。
2. 点击「保存配置」，使其持久化并用于后续执行的分析任务，无需重启。一个运行中的任务始终使用开始执行时的配置，避免两个模型阶段使用不同服务或模式。未通过连接测试也可保存有效配置。
3. 更新配置时，API Key 留空会保留已有密钥；更换服务地址必须同时填写新密钥。要移除密钥，选择规则模式并勾选「清除已保存密钥」。切回规则模式可以保留密钥供后续启用。

只有管理员可查看配置详情、保存或测试；其他登录用户只获取当前分析模式。页面配置优先于环境变量，包括已保存的规则模式。管理员同时编辑时，旧版本保存或测试会被拒绝，应重新加载最新配置后修改。配置保存和连接测试会记入操作审计，不记录密钥。

API Key 在数据库中加密保存，网页只返回是否已保存。首次保存密钥时，服务自动在数据库旁创建 `<数据库文件名>.model-key`，文件权限为 600；服务账号必须能写入数据库所在目录。数据库与加密密钥文件须作为一对保管，备份命令自动创建对应的 `<备份文件名>.model-key`，恢复命令会恢复配对密钥。迁移服务器或手动备份时也须一并复制此文件，并保持仅服务账号可读。丢失密钥文件后原有 API Key 无法恢复；在网页切回规则模式、清除已有密钥并重新填写。

未保存网页配置时，仍支持部署者提供初始环境变量，形式参考 `.env.example`；程序不自动读取 `.env`，通过终端环境变量或服务管理器加载：

- `RETAILPILOT_MODEL_PROVIDER=openai-compatible`
- `RETAILPILOT_MODEL_BASE_URL`：服务地址，默认官方 `/v1`；远端要求 HTTPS，本机可 HTTP。
- `RETAILPILOT_MODEL_NAME`、`RETAILPILOT_MODEL_API_KEY`：由部署者选择模型并配置私密密钥。
- `RETAILPILOT_MODEL_MAX_OUTPUT`：每次最大输出，默认 800，允许 100～2000。
- `RETAILPILOT_MODEL_DAILY_BUDGET`：默认 100000，按保守输入字节、输出上限及协议预留累计预约，不是账单金额或精确 token 统计。预算跨进程持久化，UTC 日期切换。

一个任务最多调用两次模型。第一角色审查已批准计划，不能扩大支持范围；第二角色从限定复核行动中选择，并引用实际证据 ID。SQL、权限、四种指标与事实摘要始终由程序产生。模型接收问题、批准计划和范围 ID，编制角色接收汇总指标；不发送逐笔交易、密码或密钥。开启前应确认数据提供方允许把这些信息发送到所配置服务。

拒绝、截断、格式错误、超时和预算不足会明确失败或澄清，不会静默伪装成模型成功。仅记录服务返回的有效数值用量字段，未返回时是未知。真实模型未在本轮配置，因此尚无真实模型正确率、费用或延迟记录。严格格式不保证语义正确，服务端仍独立校验。[官方结构化输出说明](https://developers.openai.com/api/docs/guides/structured-outputs)。

## 可选远程部署

`deploy/retailpilot.service` 提供 Linux 服务示例，`deploy/Caddyfile` 提供 HTTPS 反向代理示例。先准备域名、指向服务器的 DNS、证书获取所需网络条件及专用普通账号；这些外部条件没有在本轮验收。证书与公开域名条件参考 [Caddy 自动 HTTPS](https://caddyserver.com/docs/automatic-https)，代理配置参考 [Caddy reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)。

把程序安装到 `/opt/retailpilot`，创建独立 `retailpilot` 用户，完成依赖安装与生产构建；按实际路径调整服务文件。服务仍监听 `127.0.0.1:8000`，由反向代理向外提供 HTTPS。将私密环境配置放到 `/etc/retailpilot.env` 并限制读取权限，不把密钥写入代码仓库。Caddy 的环境中另设置 `RETAILPILOT_DOMAIN` 为真实域名。

示例只信任本机反向代理传来的请求协议，HTTPS 请求会设置 Secure 登录 Cookie。不要把 `forwarded-allow-ips` 改为任意来源。示例的两个服务进程共享本机 SQLite，通过数据库事务与租约约束任务；这不是多机集群方案。远程启用前需在目标环境核对证书、登录、域名来源检查、授权下载、备份和重启流程。
