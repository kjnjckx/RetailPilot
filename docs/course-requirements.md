## 3. 需要避免的误读

1. 零售场景符合题型方向，但最终选题认可和重复检查由教师、助教决定。
2. 课程没有提供两份评分报告的固定模板；PRD 也不是课程指定报告名称。
3. PRD 是后续需求规格说明书的输入，不能直接等同于已经完成需求建模或软件设计。
4. 多智能体是系统内部实现机制，不能仅凭“规划 Agent、SQL Agent、报告 Agent”代替业务子系统分工。
5. 原材料的提交地址、班群信息和具体日程可能对应其发布时的安排；实际提交前需核对本学期通知。

## 4. 后续追踪方法

在需求规格说明书中保留 PRD 的 `FR-*`、`NFR-*`、`UC-*` 编号；在设计说明书中把需求关联到类、接口、数据表及验证用例。多人协作时记录共享模型版本、讨论结论与变更影响，避免各自报告中的角色、指标和对象关系相互矛盾。
