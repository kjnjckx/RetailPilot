## 本次交付范围

在现有需求文档基础上完成本地 Web 初版。原有需求、课程材料及交付文档均保留，没有在项目根目录下另套一层项目目录。

三个业务模块由同一 FastAPI 服务提供，React 页面访问同源 API。SQLite 保存账号、会话、数据批次/版本、任务、报告及审计事件。金额使用人民币整数分，展示时转换为元；时间按订单携带的 +08:00 时区归属日期。

前端入口是 `src/main.tsx`，页面按业务拆分到 `src/pages/`。后端分成接口与流程、领域计算、持久化三个文件。后续可以替换数据库和问题规划器，而保留受限统计函数与权限校验。

## 已覆盖的业务规则

| 范围 | 初版实现 |
| --- | --- |
| 账号与范围 FR-01 | 三类预置账号，demo 兼具分析/管理角色；密码 scrypt 哈希、HttpOnly Cookie 会话、退出失效；角色和门店范围由后端检查 |
| 数据准备 FR-02～04 | 四表 CSV、字段映射、预览、数据校验、问题清单、显式确认、快照事务发布、重复检测；保留旧版本 |
| 指标 FR-05～06 | 固定 `sales-v1` 定义；净销售额、订单数、客单价、净销量；版本/日期/门店筛选；日趋势、门店排名与品类构成 |
| 分析 FR-07～12 | 受限自然月解析与澄清；授权检查；五阶段结构化记录；只调用预定义统计函数；取消、关联重试；门店/品类贡献；规则异常及证据指纹 |
| 报告 FR-13～16 | 草稿、正文修改、提交、审核/退回、冻结正文、新修订、草稿/正式 Markdown 导出、采纳反馈 |
| 共享 FR-17～18 | 登录、导入、发布、分析、报告和授权操作审计；固定生成的模拟数据与明确标识 |

“规则工作流”不是外部大模型驱动的多智能体实现。当前各阶段交换真实的结构化数据，数值和证据由程序计算；自然语言理解只限于代码明确支持的格式。

## 自动化验证

命令：`npm test`。测试套件共 25 项，使用临时数据库，与用户的本地演示数据库隔离。

- 固定 PRD 验收数据：华东 7 月 100,000 元，8 月 80,000 元，差额 −20,000 元，变化率 −20%；上海 −15,000 元，杭州 −5,000 元。
- 全额退款仍计有效订单数，取消订单排除，部分退款与实际退货数量分别计算。
- 金额精度、非法金额、重复主键、外键错误、退款超限、字段映射、阻止错误批次发布和重复发布。
- 完整日历序列不因缺成交日错位；门店与品类贡献分别与总体变化一致。
- 空数据与零值区分，零基期不产生无限增长率，缺时间/字段/覆盖请求澄清。
- 门店数据隔离、跨门店问题拒绝、历史任务与报告越权拒绝、授权撤销后导出拒绝。
- 管理员默认无经营数据、退出后会话失效、跨来源写请求拒绝、非法请求返回验证错误。
- 取消不再执行后续步骤、无结果禁止生成报告、重试关联、新进程恢复时终止遗留运行态。
- 草稿导出标记、先提交后审核、退回后修改重提、审核正文冻结、采纳反馈、新修订保留原版本。
- 新数据版本发布后，旧报告仍保留原快照数据。

前端验证：`npm run build` 完成 TypeScript 检查与生产构建；`uv run ruff check backend tests` 检查通过。

浏览器走查覆盖演示账号登录、总览渲染、固定问题分析、报告草稿创建和详情。桌面及窄屏页面布局进行目视检查。

## 尚未达到完整 P0 门槛

1. 无 LLM 提供商配置、提示词版本和模型调用预算；不运行任意 SQL/Python，不声称达成通用智能问数。
2. 没有冻结的 30 题问数评估集及 27/30 达标证据。
3. 尚未实测 10 万条明细、P95 响应、5 用户并发与可靠性指标。数据版本当前作为 JSON 文档保存，正式规模应迁移到版本化关系表与查询聚合。
4. 指标解释已统一，但尚未实现指标定义编辑与新指标版本发布。
5. 任务超出并发上限时返回繁忙，而非持久化排队；没有外部模型超时/重试执行器。
6. 未实现可选 customer_id 的质量提示、报告全文搜索、正式报表图形附件、Excel/PDF 和周期报告。
7. 账号是公开演示账号；外部部署前需增加账号生命周期、登录限流、HTTPS 和运维配置。本次服务只监听 127.0.0.1。

## 后续实现建议

优先为规则问题解析器加入模型适配层，但模型只能产出受约束的分析计划，仍由现有权限和统计层执行；随后冻结 30 题评估集并补齐跨年、复杂筛选与澄清会话。完成这些后，再将 JSON 快照迁移为关系表，开展规模与并发验收。
